# Story: Provisionamento de tenant isolado + subdomínio

## Context
Novo cliente aprovado cria o tenant com slug próprio (`paolaavila`) e ganha subdomínio isolado com RLS ativa.

## Sources of truth
`prd.md` Épico 1/História 1.1 · `architecture.md` §1 Fronteira B §2 · `ADR-001` · `tea-risk.md` R-1

## Acceptance criteria
- **AC-01-1:** Dado novo cliente que insere razão social, CNPJ e slug, Quando processa a requisição, Então cria registro em `Tenants`, aplica política RLS e provisiona roteamento `slug.ezragov.com.br`.
- **AC-01-2:** Dado slug já existente, Quando outro usuário tenta o mesmo, Então HTTP 409 com sugestões de alternativa.

## Restrictions
- **Out of scope:** propagação DNS/SSL → E01-S02.
- **Protected behaviors:** nenhuma tabela sem RLS + índice `tenant_id`.
- **Security:** validar CNPJ (dígitos verificadores) no servidor; slug minúsculo, `[a-z0-9-]`, max 64.

## Validation contract
- **AC → test:** AC-01-1 → integração `createTenant` + asserção de política RLS; AC-01-2 → integração duplicidade 409.
- **Required checks:** lint, type-check, build, migração Alembic valida RLS.
- **States:** loading, sucesso, erro 409.
