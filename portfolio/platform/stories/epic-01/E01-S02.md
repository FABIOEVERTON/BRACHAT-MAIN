# Story: Propagação DNS/SSL de subdomínio com fallback

## Context
Emissão automática do certificado Let's Encrypt para o domínio customizado, com fallback acessível enquanto propaga.

## Sources of truth
`prd.md` Épico 1 borda de falha · `architecture.md` §1 Fronteira A/B · `ADR-001`

## Acceptance criteria
- **AC-01-3:** Dado falha na propagação DNS/SSL, Quando o certificado não está pronto, Então o tenant permanece acessível via `app.ezragov.com.br/{tenant_id}` enquanto a emissão roda em background com até 3 tentativas (backoff exponencial).

## Restrictions
- **Out of scope:** white-label visual (logo/cores) → parte de E01-S03 de config; não bloqueia esta story.
- **Protected behaviors:** fallback nunca expõe dados de outro tenant (RLS reforçado).
- **Compatibility:** slug imutável após criação.

## Validation contract
- **AC → test:** AC-01-3 → integração com mock de emissão SSL falha → fallback responde 200.
- **Required checks:** lint, type-check, build.
- **States:** propagando, ativo, fallback.

## Notes for Shuri (Dev)
Worker de emissão com 3 retries e jitter; rota de fallback tenant-aware.

## Notes for Hawkeye (TEA)
Tests: 1 integração emissão ok, 1 integração emissão falha → fallback, 1 segurança fallback isolado.

## Done means
AC verde; fallback não vaza tenant.
