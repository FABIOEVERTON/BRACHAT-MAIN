# Story: HashChain SHA-256 encadeado

## Context

Cadeia de custódia (PRD §3.4, ADR-004): `chain_hash = SHA256(content_hash + previous_chain_hash)`; âncora = tenant_id no primeiro laudo. A cadeia nunca reinicia. Verificável externamente por perito.

## Sources of truth

- `prd.md` (§3.4) · `architecture.md` (ADR-004) · epic E0 · TEA contract
- Código `services/shared/laudo/hash_chain.py` do PRD §3.4 como base

## Acceptance criteria

- **F0-21:** Dado um content_hash, Quando `chain` é chamado e não há laudo anterior, Então `chain_hash = SHA256(content_hash + tenant_id)` (âncora).
- **F0-22:** Quando há laudo anterior, Então `chain_hash = SHA256(content_hash + previous_chain_hash)`.
- **F0-23:** Quando dois laudos são emitidos em sequência, Então o chain_hash do segundo incorpora o do primeiro (verificação independente reprodutível).
- **F0-24:** Quando um script externo recalcula a cadeia a partir dos hashes armazenados, Então o resultado bate com cada chain_hash persistido (verificabilidade — NFR Sec).

## Restrictions

- **Out of scope:** WORM (S07); numbering (S05).
- **Protected behaviors:** leitura serializada do último hash por tenant (evita corrida na cadeia).
- **Compatibility:** hashlib padrão; nenhuma dependência extra.

## Notes for Shuri (Dev)

- Touch points: `services/shared/laudo/hash_chain.py` (HashChain.hash_content, HashChain.chain), repositório de laudos (consulta último chain_hash por tenant).

- Add: teste de verificação externa documentado em `scripts/verify_chain.py` (referenciado na F0-24).

## Validation contract

- **AC → test:** F0-21 → unit âncora; F0-22 → unit encadeamento; F0-23 → integration sequência; F0-24 → script verify reproduz.
- **Required checks:** unit/integration, lint, build.
- **States:** sem laudo → 1 laudo → N laudos.
