# Story: Auth + RBAC (NextAuth v5 + JWT middleware Python)

## Context

Motor de autenticação/autorização compartilhado (PRD §3.1): NextAuth.js v5 no frontend, JWT middleware no backend Python, token 1h + refresh 7d, MFA obrigatório para TENANT_ADMIN e WHITELABEL_OPERATOR, audit log de auth no WORM (fase 0: registro).

## Sources of truth

- `prd.md` (§3.1) · `architecture.md` (seq. 3) · ADR-002 (tenant context) · epic E0
- TEA contract · `packages/types/src/auth.ts` (roles/permissions) do PRD §3.1

## Acceptance criteria

- **F0-07:** Dado um tenant ativo, Quando um usuário autentica via NextAuth, Então recebe JWT válido (1h) com claims de roles/permissions e tenant.
- **F0-08:** Quando o backend FastAPI recebe request com JWT válido, Então verifica assinatura/expiração, injeta tenant context (x-tenant-id) e aplica RBAC permission check.
- **F0-09:** Quando um usuário com role sem permissão tenta ação restrita, Então recebe 403 (RFC 7807) e o evento é registrado no audit log.
- **F0-10:** Quando refresh token expira (> 7d), Então sessão é invalidada e usuário re-autentica.
- **F0-11:** Dado user TENANT_ADMIN ou WHITELABEL_OPERATOR, Quando acessa, Então MFA é exigido antes de conceder acesso.

## Restrictions

- **Out of scope:** SAML/SSO (ADR-008 deferred); gestão de sessão white-label custom (S08).
- **Protected behaviors:** man-in-the-middle — tokens nunca logados (NFR Sec: "tokens never logged").
- **Compatibility:** NextAuth v5 (App Router); pyjwt no Python.
- **Security:** segredos via env (JWT_SECRET, NEXTAUTH_SECRET); jamais em código.
