# Story: WORMVault S3 Object Lock COMPLIANCE

## Context

Cofre imutável (PRD §3.5, ADR-003): bucket `ezra-worm-vault-prod`, Object Lock COMPLIANCE, retenção 10 anos (LGPD Art. 37), versioning, SSE-KMS chave por tenant (prod). Em dev: LocalStack (mesmo comportamento de deleção bloqueada).

## Sources of truth

- `prd.md` (§3.5) · `architecture.md` (ADR-003) · epic E0 · TEA contract
- Código `services/shared/laudo/worm_vault.py` do PRD §3.5 como base

## Acceptance criteria

- **F0-25:** Dado um PDF de laudo, Quando `WORMVault.store` grava, Então objeto é armazenado com ObjectLockMode=COMPLIANCE, retain_until = +10 anos, SSE-KMS e metadata (sha256, chain_hash, normative_refs).
- **F0-26:** Quando se tenta deletar o objeto, Então a deleção FALHA (403 ObjectLocked) — em LocalStack e em AWS.
- **F0-27:** Quando `get_signed_url` é chamado, Então retorna URL assinada válida por 1h para download.
- **F0-28:** Quando a chave não existe, Então erro claro (404) com RFC 7807.
- **F0-29:** A latência de gravação WORM (local) é < 500ms para objeto < 5MB.

## Restrictions

- **Out of scope:** gestão de chaves KMS por tenant em dev (chave compartilhada em dev — PRD §apêndice); migrations.
- **Protected behaviors:** nunca desabilitar Object Lock; retenção nunca menor que 10 anos.
- **Compatibility:** boto3; sa-east-1; LocalStack serviços s3,kms.
