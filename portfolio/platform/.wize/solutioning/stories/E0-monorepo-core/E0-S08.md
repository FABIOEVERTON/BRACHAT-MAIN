# Story: White-label (ThemeProvider + resolução de subdomínio)

## Context

White-label é modo de primeira classe (PRD §3.6, ADR-006): `WhitelabelConfig` tipado, resolução de tenant por subdomínio/domínio custom, ThemeProvider com CSS vars, hierarquia EZRA → WhitelabelOperator → EndClient.

## Sources of truth

- `prd.md` (§3.6, §8) · `architecture.md` (ADR-006, seq. 4) · epic E0 · TEA contract
- Código `apps/web/lib/tenant.ts` (WhitelabelConfig, resolveTenant) e `apps/web/components/white-label/ThemeProvider.tsx` do PRD como base; `apps/web/middleware.ts` (x-tenant-id injection) do PRD §8.2

## Acceptance criteria

- **F0-30:** Dado um hostname `prefeitura-x.ezra.com.br`, Quando `resolveTenant` é chamado, Então retorna a config do tenant com slug `prefeitura-x` (lookup por subdomínio).
- **F0-31:** Dado um domínio custom `auditoria.bancaxyz.com.br`, Quando `resolveTenant` é chamado, Então retorna a config via `customDomain` (lookup white-label).
- **F0-32:** Quando o ThemeProvider renderiza com uma config white-label, Então CSS vars (--color-primary/secondary) e branding são aplicados (sem referência visual a EZRA se hidePoweredBy=true).
- **F0-33:** Quando o laudo é emitido para EndClient sob WhitelabelOperator, Então o signatário do laudo é o operador (name/title/register), com EZRA apenas em rodapé se hidePoweredBy=false (regra de negócio crítica — PRD §3.6).
- **F0-34:** Quando `middleware.ts` resolve o tenant, Então headers `x-tenant-id` e `x-tenant-branch` são injetados para downstream.

## Restrictions

- **Out of scope:** admin de configuração white-label (FASE 5); certificados/domínios custom.
- **Protected behaviors:** hash + WORM sempre da EZRA — nunca transferíveis (implícito: chain_anchor_hash por tenant).
- **Compatibility:** Next.js middleware (edge runtime-safe); CSS vars.

## Validation contract

- **AC → test:** F0-30 → unit resolveTenant subdomain; F0-31 → unit customDomain; F0-32 → component test vars/branding; F0-33 → integration assinatura white-label no laudo; F0-34 → middleware test headers.
- **Required checks:** unit/component/integration, lint, type-check, build.
- **States:** EZRA brand default → white-label brand → hidePoweredBy.

## Notes for Hawkeye (TEA)
