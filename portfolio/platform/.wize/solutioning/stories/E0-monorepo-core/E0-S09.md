# Story: Dashboard shell Next.js App Router por ramo

## Context

Shell compartilhado da UI (PRD §2.2): App Router com roteamento por ramo — `(auth)`, `(dashboard)`, `gov-ai/{sentinel,aegis,guardian}`, `gov-municipal/{radar,vigilia,compras,executa,alerta,prova}`; `components/{ui,laudo,charts,white-label}`, `lib/` (api-client, auth, tenant). shadcn/ui base.

## Sources of truth

- `prd.md` (§2.2) · `architecture.md` (ADR-001) · epic E0 · TEA contract
- Estrutura de diretórios exata do PRD §2.2 (`apps/web/...` e `apps/admin/...`)

## Acceptance criteria

- **F0-35:** Dado o shell web, Quando navega pelas rotas `gov-ai/*` e `gov-municipal/*`, Então cada ramo tem landing placeholder e o layout do dashboard é consistente (sidebar + header).
- **F0-36:** Quando o `api-client.ts` é usado para chamar um serviço, Então injeta base URL de serviço por produto e x-tenant-id automaticamente.
- **F0-37:** Quando um laudo é exibido no componente, Então mostra hash SHA-256 e chain_hash com link de download (componente `laudo/`).
- **F0-38:** Quando o shell recebe tenant white-label, Então aplica o tema sem quebra de layout (integração S08).
- **F0-39:** A latência de navegação entre páginas do shell (dev) é < 300ms p95.

## Restrictions

- **Out of scope:** telas de produto real (Fases 1+); admin painel além do scaffold de rotas.
- **Protected behaviors:** temas white-label não quebram acessibilidade (WCAG — overlays web).
- **Compatibility:** Next.js 14 App Router; shadcn/ui; Recharts.

## Notes for Shuri (Dev)

- Touch points: `apps/web/app/(auth)/`, `(dashboard)/`, `gov-ai/`, `gov-municipal/`, `apps/web/components/{ui,laudo,charts,white-label}/`, `apps/web/lib/{api-client,auth,tenant}.ts`.
- Reuse: packages/ui (design system base) do scaffold (S01).
- Add: página placeholder por produto com rota correta (sem conteúdo de domínio ainda).

## Validation contract

- **AC → test:** F0-35 → E2E navegação shell; F0-36 → integration api-client injeta headers; F0-37 → component laudo render hash; F0-38 → component theme white-label; F0-39 → perf smoke navigation.
- **Required checks:** E2E/component/integration, lint, type-check strict, build.
- **States:** rotas vazias → placeholders render → tema white-label.

## Notes for Hawkeye (TEA)

- Tests: 1 E2E (navegação), 1 integration (api-client), 2 component (laudo, theme).
- NFR sample: navegação < 300ms p95 (F0-39).

## Done means

Shell navegável com placeholders por produto; api-client e componentes de laudo prontos; gate PASS/CONCERNS.
