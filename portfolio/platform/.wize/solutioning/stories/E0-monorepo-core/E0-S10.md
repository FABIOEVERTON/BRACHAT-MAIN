# Story: CI/CD pipeline (GitHub Actions → ECS staging)

## Context

Pipeline de integração/deploy contínuo (PRD §10.1 FASE 0:9, §6): GitHub Actions → build de workspaces + testes → push imagens ECR → deploy ECS Fargate staging. Quality gates: lint, type-check, cobertura ≥ 80%, testes, deleção WORM falha (NFR).

## Sources of truth

- `prd.md` (§6, §10.1, §11.3) · `architecture.md` (ADR-001, ADR-008) · epic E0 · TEA contract
- `infra/terraform/aws/*.tf` do PRD §6.2 (vpc, ecs, rds, s3_worm, sqs)

## Acceptance criteria

- **F0-40:** Dado um push na branch main, Quando o pipeline roda, Então os stages (install, lint, type-check, test com cobertura, build, image push, deploy staging) executam em ordem e deploy staging conclui.
- **F0-41:** Quando um teste unitário falha OU cobertura < 80%, Então o pipeline falha e não faz deploy.
- **F0-42:** Quando `teste de deleção WORM` roda no pipeline, Então a deleção falha (assert) — estágio de segurança sempre verde por construção.
- **F0-43:** Quando o deploy staging conclui, Então os serviços web + shared respondem healthcheck na URL de staging.
- **F0-44:** Segredos (AWS creds, JWT_SECRET) nunca aparecem em logs nem no código (secrets via GH Actions secrets).

## Restrictions

- **Out of scope:** deploy prod (SLA 99,5% — controles adicionais em FASE 5); rollback automático.
- **Protected behaviors:** nenhum segredo em código; região sa-east-1.
- **Compatibility:** GitHub Actions; terraform; AWS.

## Notes for Shuri (Dev)

- Touch points: `.github/workflows/ci.yml`, `.github/workflows/cd-staging.yml`, `infra/terraform/aws/**` (dos PRD §6.2), infra do staging.
- Reuse: passos do PRD §6.2 (VPC isolada, ECS por serviço, RDS Multi-AZ, S3 WORM, SQS) reduzidos para staging.
- Add: artefato `.env.example` nunca commitado com valores reais (PRD Apêndice A).

## Validation contract

- **AC → test:** F0-40 → smoke do pipeline (run bem-sucedido em run de teste); F0-41 → teste de falha induzida (commit com teste quebrado deve falhar); F0-42 → job de deleção WORM; F0-43 → healthcheck staging; F0-44 → gitleaks/scan de segredos.
- **Required checks:** análise de workflow, run de teste, lint/type/test gates no pipeline.
- **States:** push → CI → CD staging → healthy.

## Notes for Hawkeye (TEA)

- Tests: 1 workflow lint (actionlint), 1 run de teste com gates, 1 gitleaks scan.
- NFR sample: pipeline completo < 15min até deploy staging.

## Done means

Pipeline CI/CD funcional com quality gates e healthcheck staging; gate PASS/CONCERNS.
