# Story: Docker Compose dev + LocalStack

## Context

Ambiente dev local completo (PRD §6.3): Postgres 16, Redis 7, LocalStack (S3/SQS/KMS), web e serviços. Zero custo real, zero credenciais AWS (NFR Cost-01).

## Sources of truth

- `prd.md` (§6.3) · `architecture.md` (ADR-007, ADR-008) · epic E0 · TEA contract
- `.env.example` do PRD (Apêndice A) como fonte de nomes de variáveis

## Acceptance criteria

- **F0-04:** Dado `docker compose -f infra/docker/docker-compose.dev.yml up -d`, Quando os containers sobem, Então postgres (5432), redis (6379), localstack (4566) e web (3000) respondem healthy.
- **F0-05:** Quando um bucket S3 é criado no LocalStack com Object Lock COMPLIANCE, Então `aws --endpoint-url=http://localhost:4566` consegue put/head e a deleção falha (modo COMPLIANCE respeitado).
- **F0-06:** Quando um serviço exemplo (ex: sentinel container) depende de postgres/redis/localstack, Então inicia após dependências healthy (depends_on condition).

## Restrictions

- **Out of scope:** infra AWS real (S10); serviços de produto além do shared.
- **Protected behaviors:** nenhum dado real no LocalStack; região sa-east-1 configurada.
- **Compatibility:** Docker ≥ 24; compose plugin.

## Validation contract

- **AC → test:** F0-04 → `docker compose ps` healthy + curl web 200; F0-05 → script aws cli (put/head ok, delete falha); F0-06 → log de dependências.
- **Required checks:** compose config válido, healthchecks, integração LocalStack.
- **States:** containers down → up → healthy.
