# Story: scripts/generate_api_types.sh — tipos TS do OpenAPI

## Context

Geração de tipos TypeScript a partir dos OpenAPI specs dos serviços (PRD §2.2 `packages/api-contracts`): garante que o frontend usa contratos tipados idênticos aos backends — Single Source of Truth para contratos de API.

## Sources of truth

- `prd.md` (§2.2 — packages/api-contracts, scripts/generate_api_types.sh) · epic E0B · TEA contract
- OpenAPI 3.1 specs por serviço (a gerar na FASE 1+; nesta story: serviço de exemplo)

## Acceptance criteria

- **F0B-19:** Dado um OpenAPI spec de um serviço, Quando `generate_api_types.sh` roda, Então gera tipos TS em `packages/api-contracts` que compilam em strict mode.
- **F0B-20:** Quando o contrato de API muda (spec atualizada), Então a regeneração reflete a mudança e o frontend quebra no type-check até o consumo ser atualizado.
- **F0B-21:** Quando um tipo é gerado, Então segue naming consistente (PascalCase para interfaces, derivado do schema name).

## Restrictions

- **Out of scope:** geração de client HTTP (api-client da S09 consome os tipos); specs completos dos produtos.
- **Protected behaviors:** nunca editar tipos gerados manualmente (sempre regenerar).
- **Compatibility:** Node; openapi-typescript ou equivalente (decisão dev).

## Notes for Shuri (Dev)

- Touch points: `scripts/generate_api_types.sh`, `packages/api-contracts/`, `package.json` script.
- Reuse: convenção de versionamento /v1 (S01 do epic B).
- Add: CI check para diff de tipos fora de sync.

## Validation contract

- **AC → test:** F0B-19 → smoke generate + tsc strict green; F0B-20 → integration regeneração reflete mudança (teste com spec alterada); F0B-21 → unit naming.
- **Required checks:** type-check, lint, build.
- **States:** spec → tipos → regen com spec alterada.

## Notes for Hawkeye (TEA)

- Tests: 1 smoke (gera+compila), 1 integration (regeneração), 1 unit (naming).
- NFR sample: geração < 30s.

## Done means

Tipos TS gerados do OpenAPI compilam em strict; regeneração funcional; gate PASS/CONCERNS.
