# Story: Motor de jobs assíncronos (202 + job_id + SQS)

## Context

Padrão uniforme de assíncronidade (PRD §9.2, ADR-007): operações longas retornam 202 + job_id; job em SQS; status via GET /jobs/{job_id}; webhook opcional; laudo anexo quando aplicável; idempotência por job_id. LocalStack em dev.

## Sources of truth

- `prd.md` (§9.2) · `architecture.md` (ADR-007, seq. 2) · epic E0B · TEA contract
- Modelo `JobResponse`/`JobStatus` do PRD §9.2 (QUEUED/PROCESSING/COMPLETED/FAILED)

## Acceptance criteria

- **F0B-06:** Dado um job enfileirado, Quando o worker processa, Então o status evolui queued → processing → completed e o resultado (ou laudo) fica disponível em result_url.
- **F0B-07:** Quando um job falha, Então status = failed com error (RFC 7807) e retry configurado.
- **F0B-08:** Quando o mesmo job_id é submetido duas vezes, Então apenas um processamento ocorre (idempotência/dedup).
- **F0B-09:** Quando o job completa e webhook está configurado, Então o webhook do tenant é disparado com o resultado.
- **F0B-10:** Quando o status é consultado via GET /jobs/{job_id}, Então retorna JobResponse com progress_pct quando aplicável.

## Restrictions

- **Out of scope:** filas específicas de produto (Fases 1+ usam este motor); retry policy por produto.
- **Protected behaviors:** dedup key obrigatório; nunca duplica laudo na emissão.
- **Compatibility:** SQS + LocalStack; workers Python.

## Notes for Shuri (Dev)

- Touch points: `services/shared/queue/` (producer/consumer), `services/shared/api/schemas.py` (JobResponse), endpoint genérico `jobs` em cada serviço (reuso shared).
- Reuse: enums do PRD §9.2; padrão webhook configurável por tenant (config em whitelabel/tenant).
- Add: worker genérico + registro de handlers por tipo de job.

## Validation contract

- **AC → test:** F0B-06 → integration ciclo completo; F0B-07 → integration falha+retry; F0B-08 → integration idempotência; F0B-09 → integration webhook; F0B-10 → unit JobResponse.
- **Required checks:** integration, lint, build.
- **States:** queued → processing → completed/failed → consulta.
