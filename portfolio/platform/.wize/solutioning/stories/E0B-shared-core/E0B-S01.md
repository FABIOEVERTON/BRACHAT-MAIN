# Story: Conventions de API shared (RFC 7807, /v1, x-tenant-id, rate limit)

## Context

Convenções obrigatórias para todos os serviços FastAPI (PRD §9.1): x-tenant-id header, RFC 7807 Problem Details, /v1 na URL, 202 + job_id para longas, paginação por cursor, rate limit 100 req/min/tenant. `create_service()` compartilhado garante uniformidade.

## Sources of truth

- `prd.md` (§9.1-9.2) · `architecture.md` (ADR-007) · epic E0B · TEA contract
- Código `services/shared/api/conventions.py` (create_service) e `services/shared/api/schemas.py` (JobResponse, ProblemDetail) do PRD como base

## Acceptance criteria

- **F0B-01:** Dado um serviço novo criado via `create_service(name)`, Quando registra um endpoint, Então o endpoint herda automaticamente CORS (ezra.com.br), docs em /docs e OpenAPI em /openapi.json.
- **F0B-02:** Quando um endpoint retorna erro de domínio, Então a resposta segue RFC 7807 (type, title, status, detail, instance).
- **F0B-03:** Quando um request chega sem/válido x-tenant-id, Então é rejeitado (400/401/403 conforme regra) ou processado com tenant context (ver S03/S04).
- **F0B-04:** Quando um tenant excede 100 req/min, Então responde 429 com retry-after.
- **F0B-05:** Quando uma lista é paginada, Então usa cursor (não offset) conforme convenção.

## Restrictions

- **Out of scope:** auth completa (S03); jobs (S02 do epic B).
- **Protected behaviors:** nenhum serviço pode pular o create_service sem ADR.
- **Compatibility:** FastAPI; slowapi ou middleware próprio p/ rate limit (decisão dev).
