NATIVE TOOLS — FULL SCHEMAS (reference, lazy-load)
Source: opencode 1.18.10 built-in tools. Light index: reference/manifest_native_tools.txt (ALWAYS in system).

=== WHY THE SCHEMAS MUST BE IN THE REQUEST (obrigatoriedade) ===

1. TOOL-CALLING MECHANISM: opencode uses the provider's function-calling API. The model can only call a tool if its JSON schema is sent in the `tools` parameter of the request. The schema IS the contract: name, parameters, required fields, descriptions.

2. NO ON-DEMAND SUBSTITUTION: a text index (manifest) only tells the model a tool EXISTS. It does not make the tool callable. Proven empirically (2026-08-04): with all tools disabled and only the manifest in the system, the model emitted a fake tool-call in plain text, the runtime executed NOTHING, and the answer came back empty (1.688 tokens, zero action).

3. INJECTED BY THE RUNTIME EVERY REQUEST: opencode assembles the `tools` param automatically from the enabled tools in config (`tools` map). You cannot point it to a file; the schemas are generated from opencode's source code (zod schemas), not from any user file.

4. THE ONLY LEVERS ARE ENABLE/DISABLE AND THE tool.definition HOOK: a tool disabled in config (`tools: { <name>: false }`) has its schema removed from the request — and loses the ability to be called. A tool enabled is sent every request, always.

5. HOOK tool.definition (schema-slim plugin): since 2026-08-04, `~/.opencode/plugin/schema-slim.ts` replaces each enabled tool's `jsonSchema` (the schema sent to the LLM) with a compact version — property names + required + minimal types, no per-property descriptions. The `question` and `edit` tools are left intact (small/structural). Arg names MUST match the full schemas below or calls fail zod validation. Applies to registry tools only; MCP tools (`mcp__*`) are unaffected.

6. COST: the provider counts the `tools` param as input tokens, same as the system prompt. Measured on big-pickle (2026-08-04): before schema-slim, 10 enabled tools added ~4.979 tokens/request on top of the ~1.605 system prompt (total 6.584). After schema-slim: ~1.063 tokens for all enabled tool schemas (total 2.668, −3.916/request), zero functional loss (bash/read verified).

Conclusion: to reduce this cost, disable the tools the agent does not need and keep schema-slim active. The manifest + native_tools.txt are navigation/documentation, not a substitute for the `tools` param.

=== SCHEMAS (full) ===
NOTE: the full schemas below are the reference/original. What reaches the LLM is the compact version (schema-slim plugin); the "~NNN tok" labels refer to the full schema size, not the wire size.

[NT-01] bash  [ON]  (~1.322 tok)
Purpose: execute terminal commands in a persistent shell.
{ "type":"function", "function": { "name":"bash",
  "description":"Executes a given bash command in a persistent shell session with optional timeout, ensuring proper handling and security measures.",
  "parameters": { "type":"object",
    "properties": {
      "command": { "type":"string", "description":"The command to execute" },
      "timeout": { "type":"integer", "description":"Optional timeout in milliseconds (max 600000)" },
      "workdir": { "type":"string", "description":"The working directory to run the command in" } },
    "required":["command"], "additionalProperties":false } } }

[NT-02] read  [ON]  (~447 tok)
Purpose: read a file or directory from the local filesystem.
{ "type":"function", "function": { "name":"read",
  "description":"Read a file or directory from the local filesystem.",
  "parameters": { "type":"object",
    "properties": {
      "filePath": { "type":"string", "description":"The absolute path to the file or directory to read" },
      "offset": { "type":"integer", "description":"The line number to start reading from (1-indexed)" },
      "limit": { "type":"integer", "description":"The maximum number of lines to read" } },
    "required":["filePath"], "additionalProperties":false } } }
